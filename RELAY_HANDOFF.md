# Relay — session handoff

Read this first. Every session working on Relay keeps it current: update "State" and the log at the end of each phase, in the same commit as the work.

## Scope and rules (from the owner)

- **Only Relay.** Recast (branches `main`, `claude/clever-heisenberg-s3taqj`) is out of scope. Relay lives on the orphan branch `relay`.
- **Goal of the current work:** Relay should look and behave *structurally* like VS Code (and Cursor), so it no longer feels empty. Only the colours and Relay's own features (tasks, contracts, agents, records, "Needs you", change records) should stand out.
- **No fake buttons.** Every menu item, command and control either really works, or is visibly disabled with a one-line reason (e.g. "Debugging needs a debug adapter"). The command registry's `when()` returns that reason; menus, palette and buttons show it.
- **Commit and push after every phase** (`git push -u origin relay`). A previous session lost a whole phase of work because it never committed. Uncommitted work in a cloud container is gone when the session ends.
- Commit messages: plain, no model names.

## VS Code extension (owner's decision, 2026-10-22)

Developers shouldn't have to leave VS Code (its extensions, PlatformIO, debuggers) to use Relay, so Relay comes to them: `vscode/` is a VS Code extension that joins a local checkout to a Relay server. The browser IDE stays the zero-setup client (review, approvals, guests). Run its tests with `cd vscode && npm install && npm test`: a real VS Code (downloaded by `@vscode/test-electron`, run under `xvfb-run` when there's no display) against a real Relay server and a separate local clone.

- Binding (`vscode/src/fileSync.ts`): two Yjs docs per file, `doc` (shared) and `view` (exactly the editor). Keystrokes go into `view` at the editor's offsets and merge into `doc` as Yjs updates; collaborators' updates queue until a version-checked `WorkspaceEdit` writes them (VS Code refuses an edit computed on an older version: "has changed in the meantime"). Don't replace this with offset arithmetic: a one-region approximation scattered characters under concurrent edits (the "heavy interleaving" test).
- Ctrl+Z / Ctrl+Shift+Z in a shared file run `relay.undo` / `relay.redo` (Yjs undo of your own edits only), not VS Code's undo, which would revert collaborators' edits.
- A file that differs from the shared copy is never overwritten silently: setting `relay.whenFilesDiffer` (ask / useShared / shareMine).
- Presence uses the browser IDE's awareness format (user + Yjs relative-position cursor), so both clients see each other (tested with a real Chromium in `vscode/test/run.mts`).
- Getting in: the browser IDE's Share button opens `InviteDialog` (one invite, a browser link and a `vscode://relay.relay-vscode/join?invite=…` link, plus `/downloads/relay-vscode.vsix` when `vscode/` has been packaged). The extension's URI handler always asks before joining (any web page can open a vscode:// link).
- **Files both ways** (`vscode/src/fileOps.ts`): VS Code creates/renames/moves/deletes go through Relay's file API (deletes ask, `relay.shareDeletes`); Relay's are mirrored into the checkout but never over local work (a deleted file is removed here only if disk and editor hold exactly Relay's last text). Other programs' creations/deletions (git checkout, generators) are listed, never applied automatically. Every operation checks the state it finds, so replays and echoes are no-ops. Open documents keep their shared session across renames (`carry`/`landed`/`retarget` in `extension.ts`).
- **Undo from every entry point:** Ctrl+Z/Ctrl+Shift+Z are bound to Relay's undo; VS Code's own undo (Edit menu, palette) is detected by `TextDocumentChangeReason.Undo/Redo`, the text restored and Relay's undo run instead. Limitation: Edit-menu Redo after an Edit-menu undo has nothing to redo.
- **Invariant check:** every local change is applied to the editor's Yjs copy only if it reproduces the editor's new text exactly; otherwise nothing is forwarded and the person chooses (this caught a rename race that duplicated text).
- **Outside rewrites** of an open shared file (VS Code reloads it: document clean and equal to disk) are held until the person chooses (`relay.externalChanges`).
- **Protocol:** `GET /api/version` (public) returns `{ protocol, version }`; the extension (protocol 1) refuses a mismatch before spending an invite. Clients send `x-relay-client: vscode/<version>`, recorded on `member.joined`.
- **Tests:** `cd vscode && npm test` (33 tests in a real VS Code + two real-browser halves; the server is restarted mid-run; real keystrokes via `test/keys.py`, needs `pip install python-xlib`; `RELAY_TEST_ONLY=<regex>` for a subset). `npm run test:install`: the packaged `.vsix` in a normally started VS Code — install, upgrade over an older `.vsix`, the two real confirmation dialogs answered by mouse/keyboard (VS Code's test host refuses modals), restart restores the session.

### Conventions introduced (keep using them)

- `Command.native`: CodeMirror's keymap already binds the chord; the registry shows the binding but never dispatches it from the keyboard (no double-firing). `Command.editorKey`: the shortcut only applies while the editor has focus (VS Code's `editorTextFocus`). `Command.checked()`: toggle state for menu check marks.
- Chords are matched by physical key (`e.code`) with modifiers in canonical order, so `Shift+Alt+F` works on every layout and platform.
- Quick picks: `showPick({ placeholder, items })` in the Workbench opens the palette in pick mode (`CommandPalette` `QuickPick`). `quickOpen(prefix)` opens it on a prefix (`""` files, `>` commands, `:` line, `@` symbol in file, `#` symbol in workspace, `?` help).
- Menus are the `MENUS` table in `Workbench.tsx`: command ids only. A command that can't run keeps its place, greyed, with its `when()` reason as the tooltip (e.g. `NO_DEBUG`). The E2E "menus" test fails if a disabled item has no reason.
- **Save acknowledgement.** The Yjs sync protocol has no acks, so Relay adds one: a client that connects with `?ack=1` gets message type 10 (`MESSAGE_ACK` in `src/server/collab.ts`) carrying the server's state vector after the server applied and logged its update (coalesced, ~120 ms). `DocSession` compares the server's clock for its own client id with its local clock: `unsent()`, `late()` (unconfirmed > 2.5 s). The status bar says "Not saved yet" instead of "Synced" when late; closing a tab with late edits asks first. Plain y-websocket clients don't ask and never get the message.
- **An open file's session follows renames** (`DocSession.retarget`); editors are keyed by `session.id`, never by path. Undo is Yjs's `UndoManager` only (CodeMirror's `history()` is deliberately not loaded: it recorded collaborators' edits).
- Editors take keyboard focus when opened from Quick Open/symbol pickers (`focusRequest` in `Workbench.tsx`, consumed once by `Editor`). An Explorer single click keeps focus in the Explorer, as in VS Code.
- **Verification never blocks the server.** The server uses `runVerificationAsync` / `checkIntegrationAsync` (`src/core/engine.ts`, `runAsync`); the synchronous versions are for the CLI. Results are recorded against the tree they started on; if the workspace changed while they ran, the evidence's tree is `changed-during-run:<tree>` and can't satisfy the gate.
- **Applying agent work** (`AgentRunner.apply`, async): refused while Relay is still checking the run (`run.checking`, status "checking"), while another apply of it is in progress, or when a file it changed was renamed/deleted meanwhile. If the shared project changed at all since the agent's snapshot (and the task has verify commands), Relay snapshots the project as it is now, merges the agent's change into it in a temporary worktree (`.relay/worktrees/verify-*`, removed afterwards), runs `checkIntegrationAsync` there and completes the task through `approveIntegration`; it refuses if the check fails or the project moves again meanwhile.
- **Check Together = one service.** `POST /api/integrations/check` (`runs.checkTogether` for agent tasks, `relay.checkIntegrationAsync` for people's work; a mix is refused) is what the browser IDE, VS Code (`vscode/src/checkTogether.ts`) and the CLI (`relay integrate together`, via `src/remote.ts`) call. The response is the stored `Integration` plus `report` (`integrationReport` in `src/analysis/explain.ts`), which clients print verbatim — don't format results per client. The rehearsal builds on the project as it is now; `approveTogether` refuses if the shared project moved since the check. While a rehearsal runs its tasks can't be applied or checked again (`runs.isRehearsing`).
- **Explanations** (`src/analysis/explain.ts`, called from `recordIntegration` in the engine, stored in `integrations.explanation`, added by an idempotent migration in `src/core/db.ts`): built only from the dependency map (`DependencyGraph`), the runs' own diffs (`changedBy`), task scope, current contracts and the failing tests' TAP locations. Never infer from similar names; never let it change `status`. Add a new kind of cause only with a test for its confirmed, likely and unknown cases (`test/explain.test.ts`).
- **CLI talking to a server:** `relay remote join <invite>` stores `{server, cookie}` in `<db dir>/remote-session.json` (0600; `RELAY_SERVER` + `RELAY_SESSION` override). Commands that ask the server for a verdict exit 0 passed, 1 blocked, 2 usage, 3 could not complete (`RemoteError`).
- Test repos never sign commits (`test/helpers.ts` sets `commit.gpgsign=false` through `GIT_CONFIG_*` env), so the container's signing service can't fail unrelated tests.
- Server-side edits on a person's behalf use the `member:<id>` origin (`DocStore.applyEdits`), so line authorship credits that person for exactly the ranges changed.
- A document whose file is renamed or deleted is closed with WebSocket code 4410 (`CollabService.closeDocument`, then `DocStore.unload`); the client (`DocSession`) stops reconnecting and the Workbench moves or closes the tab from the `file.renamed` / `file.deleted` events.
- **Status vocabulary** (`STATUS` in `components/workbench/CoordinationView.tsx`, mirrored from `src/analysis/coordination.ts` `statusOf`): proposed, waiting, queued, running, stopped, checking, blocked, verification failed, verification required, needs review, ready to integrate, failed, cancelled, done. Each maps to engine facts (tooltip shows the engine state). Never add a UI-only state; derive it in `statusOf` and test it in `test/coordination.test.ts`. Plain task states use `StatePill` labels: Awaiting approval, Queued, Running, In review, Blocked, Failed, Cancelled, Done.
- Non-file editor tabs: `welcome:`, `relay:coordination`, `diff:…`. Use `isFileTab` / `tabLabel` in `Workbench.tsx`.
- Editor groups: `groups` + `focus` in `Workbench.tsx`; `tabs`/`active`/`setTabs`/`setActive` are the focused group's. Act on all groups with `setGroups`.
- **Themes:** `dark`, `oled`, `light` (`lib/theme.ts` `THEMES`; tokens in `app/globals.css`). OLED is Dark with every surface `#000`; only hairlines, hover and selection are lit. Add a theme by adding a token block and a `THEMES` entry; the terminal and editor read the tokens. `test/e2e/theme.e2e.test.ts` checks the surfaces are pure black. Screenshots: `node scripts/theme-shots.ts <theme> <dir>`.
- Overlays (menus, palette, notifications) are solid (`.glass` in `globals.css`), not translucent.
- Editing commands that change text go through CodeMirror transactions, so they reach collaborators as ordinary shared edits. Whole-document rewrites (Format Document) use `applyMinimalEdits` (`lib/format.ts`) so unchanged text keeps its CRDT identity, carets and authorship.

## Open gaps (after the reliability mission)

- Check Together: VS Code's "Approve and Apply…" modal is not clicked by any test (its request is tested through the API). Long rehearsals in VS Code use `fetch`, whose default header timeout is 300 s; the CLI uses `node:http` without that limit. The explanation only traces what the static map sees (JS/TS imports, property reads on a call's result); dynamic access, values passed through other functions and behaviour changes behind an unchanged interface come out as likely or unknown. A check that mixes agent work with a person's uncommitted work is refused. The explanation builds a fresh dependency graph of the combined tree on every blocked check (no cache across checks); fine for small projects, unmeasured on large ones.

- Presence after a silent network drop (no close frame) relies on the 15 s ping / 30 s heartbeat; no E2E covers that path (the abrupt-disconnect test closes the browser context).
- "Not saved yet" means the server has applied and logged the edit in its SQLite update log; writing to the file on disk follows within `flushMs`.
- The re-check on Apply only runs for tasks with verify commands; tasks without them keep the worktree gate (diff check only). The re-check refuses if anything in the project changes during the check, so a busy project may need a second Apply.
- After a refused Apply, the row's "Tested" chip still reflects the agent's worktree run; the blocker text carries the failure.
- `lineOrigin` scans the whole update log of a file per request (O(log size)); fine for now, slow for very long-lived files.
- Verification commands now run asynchronously, but still on the same machine as the server; heavy test suites compete for CPU with collaboration.
- Case-only renames are handled by inode comparison; only exercised on Linux (case-sensitive), not on a case-insensitive disk.
- An intermittent `test/testrunner.test.ts` failure was seen once in a full run before the git-signing fix; its output wasn't kept, and it didn't recur in 6 isolated and 5 full runs. Probably the same signing outage, unconfirmed.
